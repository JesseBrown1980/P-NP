## Working binary/ternary bridge

The binary widths are precise alphabets, not 64/256/1024/4096 bits:
- floor 64 is 6-bit and holds three trits;
- floor 256 is 8-bit and holds five trits (243–255 reserved);
- floor 1024 is 10-bit and holds six trits;
- floor 4096 is 12-bit and holds seven trits.

The balanced alphabet is {-1,0,+1}; code ordinals are 0/1/2.
Exact multi-word composition is allowed, including 256 + 64 for
eight trits. A valid address transform is not by itself compression.

The accepted native bridge implements reversible floor mapping,
Q-PRISM 256↔1024 packing, the 27-cell frozen matrix, and all original
40 Omnibit transforms with independent inversion.

## Scientific and engineering status

The matrix-wide binary/ternary computation passes an exact finite
criterion when a hosted native CI and separate artifact recheck pass.
It demonstrates physical data flow, lossless representation bridges,
correct integer arithmetic and backend fabric recall on measured
finite test cases. It does not determine P=NP, prove general runtime
speedups, restore every original GNN inference path, or establish a
scaling law for parallel Host8 execution.

Separate acceptance gates are required for trained GNN/FNN forward
parity, source-matched HRM inference, true concurrent worker
dispatch, full 60D physical-axis routing, independent third-party
review, memory pressure and crash/restart recall.

The architectural requirement is end-to-end *source-bound work*:
input and model source -> operator -> room -> computed result ->
independent verifier -> committed recall, with complete accounting
of all transport, model, archive and storage costs.
